# schapfl-sync-service

## Build, Package, and Deploy the Application

### Package the Application

Skip tests and package the application using Maven:
```shell script
mvn package -DskipTests
```
This creates the application package in the target folder.

### Build the Docker Image
Build the Docker image on Raspberry Pi using the following command:
```shell script
docker buildx build --platform linux/arm/v7 -t schapfl-sync-service -f src/main/docker/Dockerfile.jvm .
```
This command builds an image tagged as schapfl-sync-service.

### Run the Docker Image on Raspberry Pi
Run the container with host networking and a temporary in-memory filesystem for /tmp:
```shell script
docker run -d --name schapfl-sync-service -v /srv/sftp/pos-import/inbox:/data/pos/import --network host --restart unless-stopped --tmpfs /tmp:size=64m schapfl-sync-service
```
Ensure the container is set to restart automatically on reboot (e.g., via Docker restart policies or a system service).

## Clean up Docker Environment
```
docker system prune -a --volumes
```

### SFTP Server Requirements (Raspberry Pi)
The POS software and this service exchange files via SFTP.
Two directories are used:

•	Inbox → files generated by the service (POS reads here)
•	Outbox → optional folder for POS to drop files back (service may consume or archive)

1. Install SSH / SFTP
```shell script
sudo apt update
sudo apt install -y openssh-server
```
Verify it is running:
```shell script
sudo systemctl status ssh
```
2. Create SFTP Group and Directory
```shell script
sudo groupadd -f sftpusers
sudo mkdir -p /srv/sftp/pos-import/inbox
sudo mkdir -p /srv/sftp/pos-import/outbox

# Chroot base (must be owned by root)
sudo chown root:root /srv/sftp
sudo chmod 755 /srv/sftp

# POS import directory (accessible by sftpusers)
sudo chown -R root:sftpusers /srv/sftp/pos-import
sudo chmod -R 775 /srv/sftp/pos-import

# give ownership to the container user (uid/gid 185)
sudo chown -R 185:185 /srv/pos-import

# allow read/write for owner & group
sudo chmod -R 775 /srv/pos-import
```
3. Create SFTP User
```shell script
sudo useradd -g sftpusers -d /pos-import -s /usr/sbin/nologin posftp
sudo passwd posftp
```
4. Configure SSHD
#### Edit /etc/ssh/sshd_config:
```shell script
# SFTP only mode
Subsystem sftp internal-sftp

Match Group sftpusers
ChrootDirectory /srv/sftp
ForceCommand internal-sftp
AllowTcpForwarding no
X11Forwarding no
```

Restart SSH:
```shell script
sudo systemctl restart ssh
```
5. LAN-only Access (optional but recommended)
Restrict sshd to the Pi’s LAN IP:
```shell script
ListenAddress 192.168.1.50
```

Or use UFW to allow access only from your LAN:
```shell script
sudo apt install -y ufw
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow from 192.168.1.0/24 to any port 22 proto tcp
sudo ufw enable
```
6. Test SFTP Access
From another machine on the LAN:
```shell script
sftp posftp@192.168.1.50
sftp> cd pos-import/inbox
sftp> put test.txt
sftp> ls
```

If successful, the POS software can connect with:
•	Host: Raspberry Pi LAN IP (e.g. 192.168.1.50)
•	Port: 22
•	User: posftp
•	Password: set above
•	Directory: /pos-import/inbox

### Configure Remote Docker Access with Tailscale
1. Install Tailscale on the host machine.

Install Tailscale using the installation script:
```shell script
curl -fsSL https://tailscale.com/install.sh | sh
```
Start Tailscale:
```shell script
sudo tailscale up
```
2. Retrieve the Tailscale-assigned IP:
```shell script
tailscale ip -4
```
3. Connect to Docker Remotely

If remote Docker command execution is needed, configure Docker to listen on a secure TCP socket or create a new Docker context. For example:
```shell script
docker context create remote-docker --docker "host=ssh://risepos@100.80.80.80"
```

```shell script
docker context use remote-docker
```
Replace <TAILSCALE_IP> with the IP obtained earlier. Secure Docker with TLS when exposing remotely.
